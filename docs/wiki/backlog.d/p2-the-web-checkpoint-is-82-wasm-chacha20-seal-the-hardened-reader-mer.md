## P2 - the web checkpoint is 82 % WASM ChaCha20 seal - the hardened reader merged (#2074), the writer OFF (2026-10-12)

target: 1.8.0

The framed `state_blob` v2 (WebCrypto AES-GCM on the web, read by `mls-core` everywhere, opened by WebCrypto in the browser) takes a 7.7 MB checkpoint from ~198 to ~47 ms and the cold-start load from ~240 to ~97 ms ([performance-audit](../frontend/performance-audit-2026-10-12.md#the-webcrypto-seal-v2---measured-2026-10-12)). **READER FIRST (#2074, review 2026-10-23): the HARDENED reader ships, the writer stays OFF** - a WebCrypto refusal is `unreadable_now` and re-read, never `STATE_ALTERED`, and the verdict on the bytes comes typed from `mls-core` ([mls-protocol](../protocols/mls-protocol.md#v2---the-browser-seals-with-webcrypto-every-platform-reads-it-2026-10-12)). Why the writer waits: `v1.2.7` turns a refused v2 blob into a PIN-recovery prompt and `v1.4.0` into `STATE_ALTERED`, which rotates the identity irreversibly - [the PIN-rotation P1](p1-a-damaged-local-mls-state-is-reported-as-a-pin-rotation-and-the-pin-the-user.md) again, for any v2 blob reaching such a build (an old tab re-initialising, a web rollback). **Owed, in order (re-read 2026-11-11):** (1) DONE - `v1.5.0` is the first stable carrying #2074; (2) `minClientVersion` past that tag by [the floor rule](../legacy-compatibility.md#the-floor-rule-raised-when-both-stores-serve-the-latest-update-owner-2026-10-24), and the allowed web rollback floor with it; (3) ONLY THEN the flip of `MLS_STATE_SEAL_V2_WRITER_ENABLED` to `true`, in its OWN pull request, an alpha first and read on both bench phones' BROWSERS (user, 2026-10-18), with the reader enumeration of mls-protocol re-checked on `main`; (4) once a stable carries the flip, delete the encrypt worker and `encryptMlsStateOnMainThread` (kept until then so a revert stays one line).

**(5) After the flip: a browser that refuses its state on EVERY start** (moved here from the heavy-state audit entry, 2026-11-11). A web state that WebCrypto refuses and `mls-core` does not prove altered (`unreadable_now`) is re-read 3 times per start, then stops the login with the blob untouched - no silent repair, no rotation; the remedy is the user's, named by `auth_local_state_unreadable_now` ([mls-protocol](../protocols/mls-protocol.md#v2---the-browser-seals-with-webcrypto-every-platform-reads-it-2026-10-12)). It can only happen once a v2 blob exists: count the `stayed unreadable after 3 reads` and `bytes that mls-core OPENS` lines per browser, and only if one recurs decide what the product offers after N starts (an explicit, user-chosen reset; an export first).
