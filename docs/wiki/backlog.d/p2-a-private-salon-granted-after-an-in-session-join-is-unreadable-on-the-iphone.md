## Reading owed - a private salon granted after an in-session join is readable on the iPhone, with its badge

target: 1.7.0

**Read 2026-11-16, iPhone 12, TestFlight `1.7.0-alpha.5`, dev ([readings](../device-verification.md#the-iphone-12-readings-of-2026-11-16-fourth-sitting-b-170-alpha5)):** `gamma` joined a fresh community through the invitation card (general, `salon-a`, `salon-b` listed at once, the private salon not listed: the join half passes). `delta` then granted `gamma` the private salon through the channel access panel; `salon-prive` appeared in the rail with its lock, no reload. Three messages sent to it afterwards (a minute apart) raised **no badge**, and the opened room stayed **empty** (also five minutes later, no heal).

**What the phone log says:** `Joined channel e2085792`, then `[WELCOME] ... is a KEY-DISTRIBUTION group - installing it as a seed carrier`, `key group ... already held - redelivered Welcome ignored (idempotent)`, then `[MLS] dropped local state for ... (the server refused the external commit, minEpoch=0)`, `externalJoin REFUSED ... reason epoch_mismatch, group at 3 - attempt 1/3`, `a Welcome is owed to this device (welcome-queued) - not joining by external commit, the admitter's Welcome is the door`, then for each message `undecryptable frame ... Group not found` and `Message ... is unreadable and is not rendered - no seed for session [key:24] (repairable)`, `could not ask for 1 missing seed(s) ... Group not found`.

**Cause, from the code and that order (fixed).** The first two `[WELCOME]` lines are ONE call of `handleDistributionWelcome`: it logs `installing it as a seed carrier` before it asks whether the group is held. It was held - by this device's own external commit of the salon's key group, built on a base read before `delta`'s Add and applied to the local instance under the MLS lock, then submitted outside it. For the span of that round trip `holdsGroupState` and `isGroupActive` both answer `true` for a group the gate has not accepted, so the admitter's Welcome was taken for a redelivery and ACKed. The gate then refused the commit (`epoch_mismatch`, the Add had moved the group to 3), `externalJoin` dropped the state, and its next attempt read the seat as `welcome-queued` and waited for the Welcome just thrown away. No second Welcome is ever sent, so every seed of the salon stayed unreachable. Not a marker written when the join started: the "marker" was the MLS state itself, held before it was accepted. The fix ([channel-encryption](../protocols/channel-encryption.md#a-welcome-arriving-while-this-devices-own-external-commit-awaits-the-gate-was-thrown-away---fixed-2026-11-16)): `externalJoin` opens a window under the lock before the build and closes it once the gate's answer is applied; both Welcome handlers wait for it before reading "held". The missing badge follows from the unreadable message.

**Not the Mi's defect:** on the Mi 9T the same grant gave readable messages and only the badge was missing ([the Mi P2](reading-owed-a-salon-message-arriving-before-its-seed-raises-its-badge.md)): the race needs the Welcome to land inside the external commit's round trip.

**The reading that closes it:** the same staging on the iPhone (join through the card, then a grant of the private salon, then three messages): the room opens with the three messages and the badge shows. In the log, either `externalJoin succeeded` or `installed at epoch` for the salon's key group, and never `already held - redelivered Welcome ignored` followed by `the server refused the external commit` for the same group. When the race is met, the line `[WELCOME] key group ... arrived while this device's own external commit awaited the gate - read after its answer, held now: false` precedes the install. Then the Mi the same way. Charter: principle 2 (the essential is never lost).

**iPhone 12, `1.7.0-alpha.6`, 2026-11-16/17 (seventh sitting, [verdicts](../device-verification.md)):** iPhone half PASS (join through the card, grant, three messages: lock, badge 3, all readable; the log shows the Welcome installing the key group and no race line, so the #3691 window was not hit). The Mi half is read elsewhere; the entry closes with it.
