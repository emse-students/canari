## Reading owed - a group being created is never discovered or recovered by the device creating it (rig)

target: 1.7.0

**Built** ([chat](../frontend/modules/chat.md#between-the-registration-and-the-row-a-creating-group-looked-lost-to-the-connection-sweeps-2026-11-16)): from `registerMember` on, the server lists a group its creator has no conversation row for yet, so a connection pass running during a creation took it for a lost group - `[DISCOVERY] Placeholder <g>... created.` and `[PENDING] Group <g>... absent locally -> recovery requested`, then `[READD] ... already in WASM`. Both creation paths now mark the group before the registration is sent and release the mark once the row is written or the group deleted (`groupsInCreation.ts`), and both sweeps read that mark: discovery answers `in-creation` and writes nothing, the pending sweep leaves the rows to the creation's own Add (any it does not answer wait for the next sweep). The connection's history pass also leaves a group being created out by the same mark, and a creation that succeeded records its group as audited, so the pass no longer asks about it (`no member online ... - will ask when one returns`); a failed creation leaves it owed. `groupCreation.sweepOverlap.test.ts` runs the two real sweeps inside the window on both paths.

**It was not an `1.7.0-alpha.3` regression**: every LEAF-REFRESH-1 run of 2026-11-16 ran client bundle `9ca790c3b` (`1.7.0-alpha.2`) - only the estate moved to `dev.68983e3` - and two of the alpha.2-estate runs show the same lines. The window dates from the registration-first order of 2026-08-30.

**The reading that closes it:** on a pre-release carrying the fix, with the rig's tabs reloaded onto it (the result's `build` must name the fix's bundle, not only `estateBuild`), `bun archive/leaf.mjs --row LEAF-REFRESH-1` five times - ten creations - with no `Placeholder`, `absent locally`, `already in WASM` or `[HISTORY_RECONCILE] no member online` line on the owner's console for a group the row minted.
