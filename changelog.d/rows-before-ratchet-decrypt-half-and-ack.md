### Fixed - a message decrypted but not yet stored can no longer be lost to a checkpoint or an early acknowledgement

A checkpoint now waits for every frame between its decrypt and its row before it exports, a failed live row write (an upgrade of a notification's caption included) is kept and retried like a batch's, and an application frame is acknowledged only once ITS row is stored - per frame, so one unstorable row no longer withholds every acknowledgement; a row the store refuses for what it is (`DataError`, `DataCloneError`) is dropped at ERROR instead of stalling the device, and a frame whose dispatch throws after its decrypt is no longer taken for a decrypt failure ([chat](docs/wiki/frontend/modules/chat.md#rows-before-ratchet-the-decrypt-half-and-the-ack-2026-11-19)).
