### Fixed - the native log guard is an allowlist, and the lines it found no longer carry content

`nativeLogContent.test.ts` refuses any interpolated value in an Android, iOS or Rust log call that is not a measure, a flag, a count, an id, a status, a class name or a reviewed value, so `$it` and `${e.message}` fail where the old denylist missed them. It found, and this fixes, the v1-refused list printed whole by a refusal line, exception messages of parsing code on Android (now the class name), a whole `NSError` handed to `NSLog` on iOS, a file name logged `.public`, and the WebView navigation line that carried the identity provider's one-time `code` ([mobile](docs/wiki/frontend/mobile.md#what-a-native-log-line-may-carry-2026-10-22)).
